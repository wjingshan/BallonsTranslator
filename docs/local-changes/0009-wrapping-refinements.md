# 0009 竖排换行的两条收尾规则（整词不跨列增强、避免孤字）

- 日期：2026-10-20
- 状态：**第一步已验证；第二步已实现但未复现**（见文末）
- 前置：`0008`（整词不跨列第一版）

## 现象一：`master` 仍被拆成 `maste` + `r`

量到的证据：该块 `font_size=59.5`、`roman_word_rotation=True`，但文字框很小。
按旋转后的紧凑推进估算，六字母约 6×0.8em ≈ 285px，**大于该列可排高度**。

结论：这不是「有空间却断开」，而是「整词比一列还高」。上一版只做了「整词移列」，
对这种物理装不下的情形无效。

### 已确认的处理顺序（用户 2026-10-20 确认）

1. **优先压缩字距**：若剩余空间 ≥ 整词推进的 92%，按比例压缩该词各格的字距把它塞进当前列。
2. **压缩不足则允许溢出**：如果新起一列也压不进 92%，就把整词当作不可分割单元放置（字母不换列），
   允许纵向略微超出文字框，宁出框不拆词。

## 现象二：句尾 1~2 个字 / 一个标点被甩到下一列

标准竖排的「追い込み」问题。已确认规则：

- 某列末尾只剩 1 个字符或 1 个标点时，尝试把那 1~2 个字符**收回上一列**；
- 收回靠压缩上一列字距，**压缩上限 8%**；压到上限仍不够，则改为把上一列最后一个字符一并带到下一列，
  保证新列至少 2 格且标点不单独起列。

## 实现计划

两条都落在 `vertical_layout.py` 的逐字符循环里，需分两步、各自验证：

1. **整词**：在词首字符处先算出整词推进量，决定 `scale`（92% 下限）或「禁止拆词」标记；
   逐字符的 `tbr_h` 乘以该 scale，换列判定用整词的缩放后推进量，禁止拆词的词内字符跳过换列。
2. **孤字**：在换列发生前检查「剩余字符数 ≤ 2」，满足则对当前列施加 ≤8% 压缩并继续在本列放置；
   若压缩上限不足，则回退把当前列最后一个字符一起下移。

## 进展

1. **整词（已验证，839ac7d）**：92% 压缩后仍放不下就整词放置，并**上报多出的高度**让文字框长高
   （先尝试过「只溢出不上报」，回归测试 	est_glyph_slant_enlargement_uses_stable_bounds_and_anchor
   立刻变红：排版声称的尺寸比画出来的小，框不会长大）。用户场景复测：90×120 的框、字号 59.5，
   六字母单列，ottom = available = 196.4。
2. **孤字（已实现，未复现，ffb0ec）**：换列前若剩余仅 1–2 格、且其推进 ≤ 列高 8%，则不换列、
   把尾部留在本列并上报高度。**但所有合成几何（高 200–520、长 2–29、字号 30/59.5）都没有产生
   「只剩 1 格」的列**，从用户项目 JSON 直接构造块又撞上无关的构造错误（	ext_effects 需要
   TextEffectStack），所以这条路径**尚未得到任何真实反例的验证**。需要用户指出具体气泡编号，
   再用该块的几何量一次。

## 不做的事

- 不缩小字号（会与相邻文字不一致，用户已否决）。
- 不改动 `0003`/`0008` 的既有契约；两条规则都只在竖排 + 拉丁词/标点处生效。
